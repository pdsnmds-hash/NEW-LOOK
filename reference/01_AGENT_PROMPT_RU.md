# NEW LOOK — задание агенту на Android-приложение

Создай полноценное нативное Android-приложение на Kotlin: корпоративная визитка NEW LOOK 1 LTD EOOD + персональный бизнес-органайзер. Реализуй обе части как единый законченный продукт. Пользователь должен получать ежедневную пользу без обращения в компанию. Изучи приложенные файлы и существующий репозиторий, затем приступай к реализации. Не останавливайся на плане, макетах и заглушках.

## Приоритеты и границы

Все перечисленные основные функции входят в целевой результат. Деление на этапы — порядок разработки, а не разрешение пропустить функции. Органайзер локальный и однопользовательский: реальные совместные проекты, облачная синхронизация, сотрудники с доступами и CRM продаж в эту версию не входят. Не создавай фиктивные кнопки «пригласить команду» или «синхронизировать». Персональные рабочие данные не отправляй компании. Визитка не должна мешать работе рекламными окнами.

## Задачи — полноценный CRUD

Создание, просмотр, изменение, завершение, повторное открытие, дублирование, удаление с Undo. Поля: заголовок (обязательный), описание, проект (необязательный), приоритет low/normal/high/urgent, статус todo/in_progress/done, дедлайн с датой и необязательным временем, теги, подзадачи, напоминания, повторение. Быстрый ввод требует только заголовок; дополнительные поля в раскрываемом редакторе.

Подзадачи имеют собственный заголовок, порядок и флаг выполнения; их прогресс виден в родителе. Завершение родителя с незавершёнными подзадачами требует выбора: завершить все или вернуться. Поиск, фильтры по статусу, проекту, тегам, приоритету, наличию срока; AND между группами, OR внутри одного фильтра. Сортировка по сроку, приоритету, созданию; отсутствие срока в конце. Сохраняй настройки списка. Группы: входящие без проекта, сегодня, ближайшие 7 дней, просроченные, без срока, завершённые. Завершённые задачи не считаются просроченными.

Массовое завершение, перенос срока, назначение проекта и удаление через режим выбора. Перед массовым удалением — подтверждение количества. Свайп не должен случайно необратимо удалять данные. Пустые состояния дают понятное действие. На экране редактирования Back при несохранённых изменениях предлагает сохранить/отбросить/остаться.

## Повторение

Ежедневно, по выбранным дням недели, ежемесячно, интервал N, окончание никогда/по дате/по числу повторений. Храни серию отдельно от экземпляров: выполнение одного экземпляра не уничтожает историю и не завершает серию. При редактировании или удалении предложи «этот экземпляр» либо «этот и будущие»; прошлые экземпляры сохраняются.

Число 29/30/31 в коротком месяце переносится на последний день месяца. Пропущенные повторения не создают сотни уведомлений после долгого отсутствия: показывай пропущенные в приложении, уведомляй о ближайшем актуальном. Генерация экземпляров идемпотентная, уникальность seriesId + occurrenceKey. Используй скользящий горизонт и расширяй его при переходах календаря; не ограничивай историю фиксированной датой.

## Проекты

Создание, редактирование, описание, цвет, целевая дата, активный/архивный статус. Экран проекта: прогресс, задачи, связанные заметки и события. Вид списка и Kanban с колонками To do / In progress / Done. Перенос между колонками доступен и через меню, не только жестом. На узких экранах горизонтальный скролл или переключение колонок.

Прогресс вычисляется из фактически выполненных задач. Для проекта без задач показывай отсутствие данных. Архивация обратима и сохраняет задачи. Удаление проекта предлагает удалить с содержимым либо перенести задачи во входящие; явно опиши судьбу заметок и событий. Не удаляй связанные данные молча.

## Календарь и события

Виды месяц и повестка выбранного дня/недели. Календарь показывает задачи по дедлайну и события; различай их визуально. Выбор дня обновляет повестку. Есть переход к сегодняшнему дню, создание события и открытие связанной задачи.

Событие: название, начало/конец, весь день, место, заметки, проект, напоминание. Конец не раньше начала; события через полночь поддерживаются. Событие не становится завершённой задачей после окончания. Не запрашивай системный доступ к календарю для внутреннего календаря. Экспорт отдельного события .ics — полезная функция; создавай валидный VEVENT с UID и корректным timezone/UTC, без автоматического приглашения участников.

Срок без времени — LocalDate и не смещается при смене часового пояса. Встречи — Instant + ZoneId; показывай актуальное локальное время с понятным пояснением при отличии зоны события. Повторяющиеся задачи привязаны к локальному календарю и выбранной зоне. Обработай DST и смену системного времени.

## Напоминания

В момент включения первого уведомления объясни пользу и запроси POST_NOTIFICATIONS на требующих этого версиях Android. Отказ не блокирует остальной функционал. Показывай состояние разрешения в настройках.

Локальные уведомления для задач и событий, каналы с локализованными названиями, переход к конкретному объекту, действия «выполнить» и «отложить» для задачи. Предлагай 10 минут, 1 час и выбор времени. При завершении/удалении/переносе задачи отменяй или перепланируй уведомления. Восстанавливай расписание после reboot и изменения времени/зоны; не создавай дубликаты.

Используй AlarmManager для подходящего пользовательского времени и WorkManager для фонового обслуживания. Не обещай точность WorkManager до минуты. Для exact alarms проверяй доступ и применимость текущих правил Android; без доступа обеспечь понятный приблизительный режим, не блокируя приложение. Актуальные SDK-ограничения проверь по официальной Android-документации во время реализации.

## Экспорт, резервные копии, приватность

Экспорт выбранных задач CSV в UTF-8 с корректным quoting и защитой от spreadsheet formula injection. Полная резервная копия JSON с schemaVersion, exportDate, appVersion и всеми пользовательскими сущностями/связями. Экспорт через Storage Access Framework, без широкого доступа к накопителю.

Импорт JSON: ограничения размера и числа сущностей, валидация схемы/ID/связей/дат до записи. Предпросмотр количества объектов, замена текущего рабочего пространства только после подтверждения и предложения резервной копии. Замена атомарна; повреждённый файл не меняет БД. В первой версии поддержи надёжную замену, а не ненадёжное автоматическое слияние. Отменяй старые уведомления и восстанавливай новые только после успешного импорта. Восстанавливай расписание в том числе после сбоя между commit и перепланированием.

Честно предупреди в UI экспорта, что JSON содержит рабочие записи и не зашифрован. Не утверждай, что данные зашифрованы, если нет реализации. Без аналитики и автоматической отправки записей. Явно настрой системный backup: рабочую БД исключить из автоматического облачного backup, пользователь управляет ручным экспортом. При удалении всех данных — отдельное подтверждение и отмена уведомлений.

## Архитектура и качество

Kotlin, Compose, Material 3, Navigation Compose, ViewModel, StateFlow, Coroutines, Room с миграциями, DataStore, java.time, DI при необходимости. Совместимые стабильные зависимости; актуальные compile/target SDK проверь при реализации. Рекомендуемый minSdk 26. Раздели core/data/domain/ui; достаточно модульности, не дроби проект бессмысленно. Бизнес-логику повторений, дедлайнов, импорта и подбора вынеси из UI. Инъецируй Clock для тестов. Запросы и запись БД вне main thread. Room — источник истины, UI реактивный. Не используй destructive migration в релизе.

Планировщик должен согласовываться с БД идемпотентно; назначения уведомлений имеют устойчивые ID. Удаление сущности удаляет связи, индекс, запланированные действия. Поддержи process death, поворот, deep links уведомлений, отсутствие сети, клавиатуру, safe insets, телефоны 360–430 dp и адаптивный layout планшета.
